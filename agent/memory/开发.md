# 长短期记忆开发大纲

我的理解是分成以下几部分：

1. 工作记忆：每一轮传给大模型的提示词。 比如系统提示词+会话摘要+检索到的长期记忆+用户输入+一系列如好感度的信息。
2. 短期记忆：数据库存一个session的完整内容，交给模型的是session的摘要和最近几轮的原始信息。
3. 长期记忆：跨session的内容，如用户画像+动态内容。

# 二、短期记忆

目前我们的逻辑是按照MemoryItem来存，前面已经实现了创建，这里主要是存取。

持久化选择关系型数据库sqlite，做一个session的存储类(SessionStore)来存取MemoryItem，见`session_store.py`。

改了已有的代码：`chatagent.py`第62行加了存储类的成员变量。

同时在`chatagent.py`节点里加了存取的私有方法：`_load_short_term_memory()` 恢复摘要和最近消息，`_save_short_term_memory()` 保存本轮新增的用户、AI 和工具事件。

对于界面，`chat_window.py`里面加了个初始化的时候从sqlite里面读，然后恢复对话，**这部分代码是完全用AI写的，测试通过了**。

待优化：

- 现在会话摘要没接入大模型，就是简单搞了个规则测试能不能跑通，后面肯定要优化（`window.py`26行直接按消息数量截取，然后`chatagent.py`507行那个方法做裁剪，后面得改，是接个小模型还是啥）
- 如果开多个session（对话）跑，消息会因为并发问题展示在错误的窗口，agent回复的时候应该带session_id(SessionStore这个类弄的)，agent能拿到，但涉及的地方太多，我没敢改。

# 三、长期记忆

按照用户画像+动态的跨session记忆来处理。

新增三个文件：

- long_memory.py 管理长期记忆
- user_profile.py 用户数据模型
- profile_store.py sqlite存用户画像

已有的相关文件：

- classifier.py 提取候选记忆
- store.py 动态记忆存储
- retriever.py 动态记忆检索

**完整流程**

```text
用户输入
  ↓
读取固定用户画像（全部读取）
  ↓
检索相关动态记忆（Top_K）
  ↓
画像 + 动态记忆 + 会话摘要 + 最近消息
  ↓
chat_agent
  ↓
llm从本轮对话提取长期记忆候选
  ├─ 更新画像
  ├─ 保存稳定/临时偏好
  ├─ 保存事实
  └─ 必要时保存情节
```



## 3.1 用户画像

## 3.2 跨session动态记忆

分语义，情节和程序性记忆（这篇综述很猛：https://arxiv.org/pdf/2512.13564）。

| type       | 例子                                             | 生命周期           |
| ---------- | ------------------------------------------------ | ------------------ |
| 语义记忆   | 我喜欢川渝妹子、我在学langchain                  | 终身或者有过期时间 |
| 情节记忆   | 上次用户写不出来代码内耗了，我帮助他一点点讲代码 | 长期、按相关性召回 |
| 程序性记忆 | 以后先共情我，让我停止内耗，再客观性的给建议     | 确认后长期生效     |

通过设定生命周期，带个过期时间，正好就和以前咱们说的“事件的完成时间”对上了，这样按条管理很不错。
